# H20 执行手册（2026-10-22）

目标：在新 H20 上把 MPCache 的 **CogVideoX-2B 49 帧生产协议**跑完，并把 Wan / HunyuanVideo 的权重预取好。
所有命令都可直接复制执行；每一步都有“检查点”，不通过就停下，不要继续。

---

## 0. 先确认机器与环境（30 秒）

```bash
nvidia-smi --query-gpu=name,memory.total --format=csv
df -h /root
python3 --version || true
ls /root/miniconda3/bin/conda || echo "no conda"
```

**检查点**
- 至少一张 H20-96GB，显存 96GB 左右；
- `/root` 剩余 ≥ 150 GB（权重约 100 GB）；
- 有 `/root/miniconda3`（没有就先装 Miniconda，命令见文末附录）。

## 1. 从你本机（或 V100）把代码传上来

代码目录很小（几百 KB），从 **V100** 拷最省事（假设你本机能 ssh 两台机器）：

```bash
# 在 V100 上打包（或在本机 ~/Desktop/论文和资料/ViewDiT 打包）
tar czf /tmp/mpcache_code.tgz \
  experiments/video/mpcache_controller.py \
  experiments/video/step_oracle.py \
  experiments/video/g0a_gap.py \
  repro/

# 传到 H20（把 <H20> 换成你的登录串）
scp /tmp/mpcache_code.tgz <H20>:/root/
```

在 H20 上：

```bash
mkdir -p /root/viewdit && cd /root/viewdit
tar xzf /root/mpcache_code.tgz
ls experiments/video/mpcache_controller.py experiments/video/step_oracle.py repro/
```

**检查点**：两个 .py 都在，`repro/` 里有 `bootstrap_h20.sh`、`H20_BOOTSTRAP.md`、`ABLATIONS.md`。

> 注意：`mpcache_controller.py` 里把 `ROOT` 写死为 `/root/viewdit`。如果你换路径，必须先改这一行：
> `sed -i "s|ROOT = Path('/root/viewdit')|ROOT = Path('/你的/路径')|" experiments/video/mpcache_controller.py`

## 2. 建环境（约 10 分钟）

```bash
export HF_ENDPOINT=https://hf-mirror.com
bash /root/viewdit/repro/bootstrap_h20.sh /root/viewdit
```

这个脚本会：
1. 建 `racfg` conda 环境（python 3.10）；
2. 装 pin 住的包（torch 2.10.0+cu128、diffusers 0.37.0、transformers 5.2.0 等）；
3. **下载三套权重**（Cog 13G + Wan1.3B 27G + HunyuanVideo ~60G，带断点续传）；
4. 跑一条 Cog 冒烟（N=13，reuse + tea_gap）。

**检查点**
- 脚本最后打印出两行 `reuse / tea_gap` 结果，且没有 NaN；
- `python` 一律用 `/root/miniconda3/envs/racfg/bin/python`，**不要用系统 python**（没有 numpy）；
- 下载中断是常见的：**不要删目录**，重新执行同一条命令即可续传。

## 3. 生产协议：CogVideoX-2B，49 帧，100 prompt（今晚的主力任务）

先跑一条确认 49 帧能跑、显存够：

```bash
cd /root/viewdit
P=/root/miniconda3/envs/racfg/bin/python
$P experiments/video/mpcache_controller.py \
  --frames 49 --nprompt 1 --seeds 3000 --Ns 13 \
  --planners reuse,tea_gap \
  --out /root/viewdit/results/video/smoke49
```

**检查点**：日志里 `one CFG step ...` 的耗时 / 显存峰值；两条结果都出且不为 NaN。

确认无误后，挂后台跑全量（约 6–8 小时）。100 个 prompt × 1 个 seed（3000，与我们的开发协议一致）：

```bash
cd /root/viewdit
mkdir -p logs
setsid nohup /root/miniconda3/envs/racfg/bin/python experiments/video/mpcache_controller.py \
  --frames 49 --nprompt 100 --seeds 3000 \
  --Ns 10,13,17 --planners reuse,tea_gap \
  --out /root/viewdit/results/video/cog49_prod \
  > logs/cog49_prod.log 2>&1 < /dev/null &
```

**检查点**（每 10 分钟看一次）

```bash
wc -l /root/viewdit/results/video/cog49_prod/closed.jsonl   # 每 30 分钟应增加
tail -3 /root/viewdit/logs/cog49_prod.log
nvidia-smi --query-gpu=utilization.gpu,memory.used --format=csv,noheader
```

总行数应为 `100 prompt × 3 预算 × 2 方法 = 600`。跑到 600 就完成。

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| `ModuleNotFoundError: numpy` | 用了系统 python，改用 `/root/miniconda3/envs/racfg/bin/python` |
| 下载卡住 / handshake timeout | 重跑同一条下载命令，会自动续传；不要 `rm -rf` 目录 |
| `huggingface-cli` 不存在 | 正常，脚本用的是 python API |
| 显存不足 | 49 帧 Cog-2B 峰值约 11–12 GB，若报 OOM 先跑 `--nprompt 1` 冒烟确认 |
| 想确认任务还活着 | `ps -eo pid,etimes,cmd \| grep mpcache`，**不要用 `pgrep -f`**（会匹配到 ssh 命令本身） |
| 中途要停 | `pkill -f "out /root/viewdit/results/video/cog49_prod"`，JSONL 是追加写，已完成的不会丢 |
