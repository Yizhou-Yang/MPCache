# Wan2.1-T2V-1.3B 主表（2026-10-29，新 H20，全部同机同参考）

**口径**：前 50 个 VBench prompt，seed = prompt index，negative `animation`，81 帧 832×480，
UniPC-50 步、flow shift 3、CFG 5。参考 = RA harness `--mode original`（50 步全量，本机重跑）。
指标 = `repro/metrics.py`（LPIPS-alex / SSIM / PSNR，帧间均值）。

| 方法 | LPIPS ↓ | SSIM ↑ | PSNR ↑ | n | 加速 |
|---|---:|---:|---:|---:|---:|
| **RA-CFGCache（Slow，默认）** | **0.1022** | **0.8598** | **27.88** | 50 | ~2.6× |
| TeaCache | 0.1760 | 0.7686 | 22.99 | 50 | ~2.5× |
| **ours `tea_gap`（N=19）** | **0.1909** | 0.7360 | 21.85 | 50 | 2.63× |
| **ours `fr`（隐藏层残差，N=19）** | **0.2075** | 0.7321 | 21.89 | 50 | 2.63× |
| TaylorSeer | 0.3585 | 0.5870 | 17.24 | 50 | ~2.5× |

## 结论（诚实版）

1. **我们没有超过 RA-CFGCache**：0.1909 vs 0.1022，差 **87%**；也略差于 TeaCache（0.1760）。
2. **残差重建（`fr`）在我们手里比 `tea_gap` 更差**（0.2075 vs 0.1909）——说明我们的 `fr` 实现**不等价**于 RA 的 CFGCache。
3. 因此 RA 的优势**不能只归因于“隐藏层残差”这一机制**：同样的机制在我们手里是 0.2075，在 RA 手里是 0.1022。差异来源尚未定位（候选：跳步位置/分支决策/残差作用位置）。

## 发现的实现问题

- **`CFGCache-fast` 与 `CFGCache-slow` 结果逐位相同**（0.1022/0.8598/27.88，完全一致）：
  `--rel_l1_thresh 0.30` 与 `0.60` 对 CFGCache 模式无效（该参数只对 TeaCache 生效，见 `cal_type.py`）。
  → 主表里**不能**把两者当不同配置；RA 的 Slow/Fast 需要他们的真实阈值（`cfgcache_joint_action` 内部），
  或改用他们论文给出的两条曲线分别标定。
