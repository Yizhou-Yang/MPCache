## 5. What this establishes

- **Quality metrics reproduce the paper within noise** across all eight comparable rows:
  |ΔLPIPS| ≤ 0.0084, |ΔSSIM| ≤ 0.0156, |ΔPSNR| ≤ 0.47. This holds with bf16 on H20, i.e. the
  paper's precision, and with a different solver stack path than the V100 fp16 runs.
- The `wan + TaylorSeer` row — the one deferred from V100 because its cache needed 90–135 GiB —
  **ran to completion on 96 GiB with no OOM and no memory adapter** (LPIPS 0.3496, 100/100 videos).
  Measured peak with an isolated single-prompt probe: **65.13 GiB** (66695 MiB, 117 samples at 2 s),
  i.e. ~30 GiB headroom on a 95.6 GiB card, well under the 130 GiB go/no-go threshold.
  See `audit/WAN_TAYLORSEER_MEMORY.json`. The original 90–135 GiB figure was a V100-derived
  estimate and over-predicts the bf16 footprint on this card.
- Speedup numbers are in the same family (2.4–3.7×) but are **not** comparable to the paper:
  different silicon, and latency is chunk-averaged over shared-GPU wall clock.

## 7. Honest limitations (must accompany any table taken from here)

1. H20 ≠ H200. Quality is comparable; latency/speedup is not.
2. TaylorSeer on CogVideoX is an extra row — RA-CFGCache Table 1 has no such row.
3. The upstream CFGCache threshold-binding bug had to be fixed (`cfgcache_thresh = rel_l1_thresh`);
   this is a real deviation and must be declared in the reproduction section.
4. No statistical-gate test was run. Nothing here supports an MPCache SOTA claim.
5. G0a cost-model evidence remains **FAIL**; this run does not alter it.
6. Per-prompt latency is not available: the harness emits one `Saving time:` summary per process.
