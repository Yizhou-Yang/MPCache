# H20 reproduction audit bundle

Generated by `repro/audit_pack.py` (runnable, deterministic, no GPU needed):

```bash
VIEWDIT=/root/viewdit python3 repro/audit_pack.py
```

Outputs live in `audit/` on branch `h20`.

## Why this bundle exists

The goal is that a reviewer can **audit the run from the committed artifacts alone**, without
re-executing a 100-prompt × 6-row × 2-backbone GPU schedule.

## Contents

| file | what it proves |
|---|---|
| `audit/MANIFEST.json` | SHA-256 + byte size of **every** artifact produced by the run, including the `.mp4` videos that are deliberately not committed (see below). 2237 entries / ~980 MB of outputs at time of writing. |
| `audit/ENVIRONMENT.json` | GPU model / driver / compute capability, CUDA, python, exact package versions, pinned upstream commits, prompt-file count, and the protocol flags actually used (bf16, no offload, no tiling, no encoder parking). |
| `audit/TRACE_STATS.json` | per-log statistics: kept lines, number of CFGCache decision steps, action histogram (`full_both` / `reuse_both` / ...), and wall-clock timing figures present in the log. |
| `audit/logs_clean/*.log` | the **complete** run logs with ANSI escapes and tqdm progress bars stripped. Nothing else is removed — every `CFGCache step N: dhat=... ghat=... rhat=... tau=... accumulated_risk=... action=...` line is preserved. |

## How to audit without re-running

1. **Environment fidelity** — read `ENVIRONMENT.json`: `dtype=bfloat16`, `cpu_offload=false`,
   `vae_tiling=false`, `text_encoder_parking=false`, `steps=50`, prompt file has 100 non-empty lines,
   and the three upstream commits match `H20_MIGRATION.md`.
2. **Coverage** — `MANIFEST.json` lists exactly which `videos/video_XXXXXX.mp4` exist per row. Count by
   prefix to confirm `100` per row.
3. **Method behaviour** — read `logs_clean/*_racfg_*.log`. The controller trace is line-addressable:
   each decision step records the estimated quantities and the chosen action, so the caching policy can
   be re-derived without the model.
4. **Artifact identity** — if you obtain the videos through any other channel, verify them with:
   ```bash
   sha256sum videos/video_000000.mp4   # must equal the value in MANIFEST.json
   ```
5. **Timings** — the harness emits one summary `Saving time:` line per process, not per video. This is
   recorded as-is in `TRACE_STATS.json`; per-video latency must not be inferred from it.

## Deliberate exclusions

- **Videos are not committed.** `*.mp4` is ignored by the repo (size). `MANIFEST.json` is the
  integrity anchor for them.
- **No weights, no upstream clones** (`weights/`, `repro/upstream/` are environment, not artifacts).
- **No secrets**: no tokens, no `.hf_token`, no SSH material.

## Standing caveats (must survive into any paper table)

- H20 ≠ H200. Quality metrics are comparable (same bf16, same seeds, paired same-hardware Vanilla50);
  latency/speedup are **not** comparable to the published H200 numbers.
- TaylorSeer on CogVideoX is an extra row; RA-CFGCache Table 1 has no such row.
- The CFGCache threshold binding fix is a real protocol deviation and must be stated.
- Reproducing baselines yields no MPCache SOTA or statistical-gate claim.
- G0a cost-model evidence remains **FAIL** and is unaffected by this run.
